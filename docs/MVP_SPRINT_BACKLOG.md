# MVP 스프린트 백로그 (12주, 2주 x 6스프린트)

## 1. 운영 원칙
1. 각 스프린트는 배포 가능한 산출물을 남긴다.
2. 실거래 기능은 모의투자 안정성 검증 후 단계적으로 활성화한다.
3. 수익률 목표보다 리스크 통제 기능 완료를 선행한다.

## 2. 팀 가정
1. Product Manager 1
2. Frontend Engineer 1
3. Backend Engineer 2
4. Quant/ML Engineer 1
5. DevOps 1 (파트타임 가능)
6. Designer 1 (파트타임 가능)

## 3. 에픽 구조
1. EPIC-A: 인증/구독/결제
2. EPIC-B: 거래소 연동/주문 실행
3. EPIC-C: AI 신호/리스크 엔진
4. EPIC-D: 실시간 대시보드/리포트
5. EPIC-E: 운영/보안/관측성

## 4. 스프린트 계획

### Sprint 1 (주 1-2): 플랫폼 골격
목표:
1. 사용자 로그인과 기본 결제 플로우 가동
2. 백엔드 기본 골격과 공통 인프라 구축

주요 작업:
1. `A-01` 이메일/소셜 로그인 + JWT + 2FA 기본
2. `A-02` Stripe 결제 세션 생성 및 Webhook 수신
3. `E-01` API Gateway, 공통 에러코드, 로깅 미들웨어
4. `E-02` PostgreSQL/Redis 기초 스키마 및 연결
5. `D-01` 대시보드 와이어프레임 UI 스켈레톤

완료 기준:
1. 사용자가 회원가입 후 결제 성공 시 `Pro` 권한 획득
2. API 기본 헬스체크/로그 수집 가능

### Sprint 2 (주 3-4): 거래소 연결 + 모의주문
목표:
1. 거래소 API 계정 연결
2. 모의투자 주문 생성/체결 시뮬레이션

주요 작업:
1. `B-01` 거래소 API 키 등록/암호화 저장/KMS 적용
2. `B-02` 계정 권한 검증(조회/거래)
3. `B-03` 모의주문 엔진(시장가/지정가 기본)
4. `D-02` 주문내역/잔고 기본 대시보드
5. `E-03` 감사로그 테이블/추적 ID 연동

완료 기준:
1. 모의투자 모드에서 주문 생성~체결~대시보드 반영 성공
2. 키 검증 실패 케이스 사용자 안내 메시지 표시

### Sprint 3 (주 5-6): 신호 v1 + 리스크 v1
목표:
1. AI 신호 생성 파이프라인 v1
2. 핵심 리스크 룰 적용

주요 작업:
1. `C-01` 시장 데이터 수집기 + 피처 파이프라인
2. `C-02` 신호 모델 v1 (baseline)
3. `C-03` 리스크 룰(일손실, 포지션 한도, 변동성 제한)
4. `B-04` 주문 전 리스크 검증 연동
5. `D-03` 리스크 이벤트 UI 패널

완료 기준:
1. 리스크 룰 미통과 주문이 차단되고 이벤트 기록
2. 신호 기반 모의 자동매매 24시간 연속 실행 성공

### Sprint 4 (주 7-8): 실시간화 + 알림
목표:
1. WebSocket 실시간 스트리밍 완성
2. 경보/리포트 자동화

주요 작업:
1. `D-04` WebSocket 채널(체결/손익/리스크)
2. `D-05` 실시간 PnL, 자산배분, 전략별 성과 카드
3. `D-06` 알림(이메일/메신저) 연동
4. `E-04` 모니터링 대시보드(Prometheus/Grafana)
5. `E-05` 장애 알림 룰 구성

완료 기준:
1. 체결 후 5초 내 UI 반영(p95)
2. `HIGH` 리스크 이벤트 1분 내 알림 발송

### Sprint 5 (주 9-10): 베타 하드닝
목표:
1. 안정성/보안/성능 강화
2. 소규모 베타 사용자 운영 가능 상태

주요 작업:
1. `E-06` 레이트 리밋/봇 방어/권한 강화
2. `E-07` 주문 재시도/서킷브레이커/멱등성 강화
3. `C-04` 백테스트 리포트 자동 생성
4. `A-03` 플랜 변경/해지/결제 실패 재시도 플로우
5. `D-07` 사용자 온보딩 개선(체크리스트 방식)

완료 기준:
1. 베타 사용자 20명 온보딩 및 2주 무중단 운영
2. 핵심 API/주문 경로 성능 목표 만족

### Sprint 6 (주 11-12): 출시 준비
목표:
1. 운영 플레이북 완성
2. 정식 출시 기준 충족

주요 작업:
1. `E-08` 운영 런북(장애, 거래소 다운, 긴급정지)
2. `E-09` 보안 점검/취약점 수정/감사로그 검증
3. `A-04` 약관/개인정보/면책 UI 반영
4. `D-08` 일간/주간 성과 리포트 자동 발행
5. `PM-01` GA 체크리스트 및 KPI 트래킹 대시보드

완료 기준:
1. 출시 Go/No-Go 체크리스트 100% 충족
2. 운영자 핫라인/알림/복구 훈련 완료

## 5. 우선순위 백로그 (P0/P1/P2)
### P0 (출시 필수)
1. 인증/결제/구독 권한 제어
2. 거래소 키 암호화 저장 및 검증
3. 모의주문 + 리스크 차단 + 실시간 체결 표시
4. 감사로그/장애알림/Kill Switch

### P1 (출시 직후 고도화)
1. 다중 전략 비교 UI
2. 고급 리스크 지표(Var, CVaR)
3. 고급 리포트/코호트 분석

### P2 (중장기)
1. 다중 거래소 동시 최적 라우팅
2. 전략 마켓플레이스
3. B2B API 제공

## 6. Definition of Done (DoD)
1. 코드 리뷰 1인 이상 승인
2. 단위/통합 테스트 통과
3. 모니터링 지표/로그/알림 연결
4. 문서(운영/API/릴리즈 노트) 업데이트
5. 보안/권한 체크리스트 통과

## 7. 리스크 버퍼 계획
1. 각 스프린트 용량의 15%를 버그/운영 이슈에 예약
2. 외부 API 장애 대응을 위한 대체 시나리오 상시 유지
3. 모델 성능 저하 시 룰 기반 보수 모드로 자동 전환

## 8. 출시 전 최종 게이트
1. 주문 실패율 < 0.5%
2. 실시간 지연 p95 < 3초
3. 일손실 한도/비상정지 시나리오 테스트 100% 통과
4. 법무/컴플라이언스 검토 승인
